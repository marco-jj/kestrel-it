# 01 — Database Schema & Drizzle ORM Mapping (PostgreSQL)

Questo documento consolida le **513 migrazioni** in [`../snipe-it/database/migrations/`](https://github.com/grokability/snipe-it/tree/576e1c3c9e1ad67b7c7d53dcde49b9b7b5d253f8/database/migrations) e i **53 modelli** documentati in [`../snipe-it/_ide_helper_models.php`](https://github.com/grokability/snipe-it/blob/576e1c3c9e1ad67b7c7d53dcde49b9b7b5d253f8/_ide_helper_models.php) in uno schema **PostgreSQL 16+ / Drizzle ORM** pulito, normalizzato e privo di mutazioni DDL a runtime.

---

## 1. Convenzioni Generali dello Schema Drizzle (`apps/api/src/db/schema/`)

1. **Primary Keys:** `serial('id').primaryKey()` (o `integer('id').primaryKey().generatedByDefaultAsIdentity()` in PostgreSQL, per consentire l'inserimento esplicito degli ID storici durante la migrazione da Snipe-IT in Fase 4).
2. **Timestamps & Soft Deletes:** Tutte le entità principali utilizzano un helper condiviso:
   ```ts
   export const timestamps = {
     createdAt: timestamp('created_at', { withTimezone: true }).defaultNow(),
     updatedAt: timestamp('updated_at', { withTimezone: true }).defaultNow(),
     deletedAt: timestamp('deleted_at', { withTimezone: true }),
   };
   ```
3. **Valori Monetari:** Tutte le colonne `purchase_cost`, `default_purchase_cost`, `cost`, `unit_cost`, `depreciation_min` usano `numeric('...', { precision: 20, scale: 2 })`.
4. **Relazioni Polimorfiche di Snipe-IT:**
   Snipe-IT utilizza coppie `(assigned_to, assigned_type)`, `(item_id, item_type)`, `(target_id, target_type)`, `(checkoutable_id, checkoutable_type)`, `(requestable_id, requestable_type)`.
   - In Kestrel-IT manteniamo le coppie `(id, type)` per piena compatibilità con i log, i report e la migrazione dati, ma normalizziamo i valori `type` da stringhe namespace PHP (`App\Models\User`, `App\Models\Asset`, `App\Models\Location`) a un **enum PostgreSQL canonico** (`'user' | 'asset' | 'location' | 'license' | 'license_seat' | 'accessory' | 'consumable' | 'component' | 'model' | 'company' | 'department' | 'supplier' | 'maintenance'`), con un converter automatico nel tool di migrazione Fase 4.
